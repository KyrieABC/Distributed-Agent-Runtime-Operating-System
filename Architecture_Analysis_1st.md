# Runtime Architecture and Subsystem Connection
  - platform divided into **global control plane**, multiple **execution cells**, and **event plane**, a **state plane**, and an **observability plane**
  1. **Global Control Plane**: Exposes APIs, authenticates principles (core rules used to verify user or device identity securely), validate agent specification (check if agent's built behavior matches its planned design, safety boundaries, and expected task performance), stores desired state, manages versions and deployment, evaluates quotas and budgets, and selects an execution cell 
     - *Deployment*: Process of shipping an application from a developer's computer or test environment onto a live server or user device where it can run and be used in real world
     - *execution cell*: Individual source code block inside an interactive software environment that can be ran independently to see immediate result
  2. **Execution Cell**: Each cell contains 1 or more Ray clusters, a local execution gateway, worker pool, MCP egress control, telemetry collector, local Kafka brokers(optional)
     - *ray cluster*: Group of connected Node that runs heavy AI applications across multiple machines together
     - *execution gateway*: Safely handle, inspect, and route tasks, tool calls, or data before they each external systems or cloud services
     - *worker pool*: Limits and manages concurrency by maintaining a fixed number of background workers (threads) that continuous pull and process tasks from a shared queue, prevent resource exhaustion by too much operations creation
     - *MCP egress control*: Restricts and monitors outbound network traffic and data flows generated by AI agent tool calls
     - *Kafka brokers*: Core server node that store, replicate, and manage data streams
     - A cell may cell may correspond to: A region/availability-zone group/business unit/regulated environment/accelerator type/trust tier
     - Scheduler returns a stable cell assignment, the *run coordinator* then submits Ray tasks and actor inside that cell
  3. **Run execution model**: A run (a single end-to-end execution of a process (Ex: *executing a CI/CD pipeline*, *running an LLM agent workflow*)) is a durable (Every step is persisted to persist storage for fault tolerance and re-readability) platform entity (A component tracked within a network or observability platform) that contains tasks, actor session, tool invocation, approvals, checkpoints, and child runs
     ```
     Lifecycle:
     Submitted
       -> Admitted
       -> Assigned to Cell
       -> Starting
       -> Running
       -> Waiting for tool | Waiting for event | Waiting for approval
       -> Succeeded | Failed | Canceled | Timed out
     ```
     - Each task attempt has a separate state machine:
       ```
       Pending -> Leased -> Dispatched 
       ```
